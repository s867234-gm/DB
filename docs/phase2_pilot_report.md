## 二、复权机制与历史因子永久锁定原则

1. **历史因子永久锁定**：

   - 建库时直接从旧库抽取 `adj_factor`（截至 2026-10-30 股票最新复权因子为 `1.0`；指数复权因子恒为 `1.0`；分钟线取对应 `trading_date` 当日的日线 `adj_factor`）。
   - **2026-10-30 及之前的 `adj_factor` 永久锁定不变**。未来发生除权除息时，**不修改历史行**，而是通过累乘向后推进除权日及以后的 `adj_factor`，并同步更新 `security_info.latest_adj_factor`。
2. **多周期合成极值基准**：

   - 在合成多周期高低点与计算 RSV 时，严格统一采用复权价格计算：
     $$high\_adj = high \times adj\_factor, \quad low\_adj = low \times adj\_factor, \quad close\_adj = close \times adj\_factor$$

## 三、Numba JIT 规则 A 多周期 KDJ 引擎设计与验证 (`src/kdj_engine.py`)

### 3.1 规则 A（动态快照 + 已闭合桶前值锚定）算法实现

- **桶划分规则**：
  - 日线周期 $N \in \{1, 2, 4, 8, 16, 32\}$：按每只标的自身的 `bar_seq` 从首根日线（0-based）起分桶，当 `(bar_seq + 1) % N == 0` 时该桶正式闭合。
  - 分钟线周期：每个交易日内固定 16 根 slot（1~16），`15m` 每 1 slot 闭合；`30m` 在 `slot_seq % 2 == 0` 闭合；`60m` 在 `slot_seq % 4 == 0` 闭合；`120m` 在 `slot_seq % 8 == 0`（即 11:30 与 15:00）闭合。
- **前值引用与状态定型**：
  - 动态快照在任一时间点 $t$ 计算时，引用的前值 $(SK_{prev}, SD_{prev}, MK_{prev}, MD_{prev})$ **严格取自上一个已闭合桶闭合定型时的指标值**。
  - 仅当触发当前桶闭合时，才将当前算出的指标正式写入已闭合定型值，并将当前桶的高低点推入历史闭合桶环形窗口（最多维护 104 根已闭合桶）。
- **分钟线预热机制**：
  - 分钟线计算从 2024-09-06 起的全部数据进行递推预热，输出时截取 `trading_date >= '2024-10-01'` 的数据写入 `minute_snapshot`，确保 2024-10-08 节后首日的指标拥有充足的历史窗口支撑，杜绝冷启动失真。

### 6.2 全市场 5,335 只标的迁移总耗时预估

全市场共收录 **5,335 只标的**（5,228 只股票 + 107 只指数）：

1. **单进程单线程预估**：
   - 平均每只标的提取与写入开销约 0.25 秒；
   - 5,335 只标的单线程串行耗时约：$$5335 \times 0.25\text{s} \approx 1333\text{s} \approx 22\text{ 分钟}$$；
2. **多进程并发迁移预估（以 8~16 核多进程并行）**：
   - 采用 `multiprocessing` / 多工作进程分批并发，DuckDB 配合分片并行；
   - 预计全市场 5,335 只标的全量历史构建与入库总耗时可压缩至 **3 ~ 5 分钟以内**！
3. **日常增量更新耗时预估**：
   - 在日常收盘或分钟级盘中增量时，基于 `incremental_state`，单标的单根 bar 仅需几微秒即可完成更新；
   - 全市场 5,335 只标的每日增量更新预计可在 **2 ~ 5 秒内** 瞬间完成！
